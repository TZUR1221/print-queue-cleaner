# איפוס תור הדפסות

**מה זה:** יישום שרץ על המחשב כל 2 דקות ומוחק מתורי ההדפסה עבודות שנתקעו.
**למה:** עבודה תקועה חוסמת את כל התור ואז אף אחד לא מצליח להדפיס. במקום לרוץ ל"מכשירים ומדפסות" ולבטל ביד — המחשב מנקה את עצמו.
**איך מריצים:** לוחצים פעמיים על `הפעלה.bat` ← חלון הגדרות בעברית. ההרצה האוטומטית מותקנת מהחלון (כפתור "הפעל כל 2 דקות") ומופיעה ב-Task Scheduler בשם `PrintQueueCleaner`.
**GitHub:** טרם
**סטטוס:** חי — **גרסת ה-exe** מותקנת ב-`C:\PrintQueueCleaner` ורצה (מ-25/11/2026). גרסת הסקריפטים נשארת כקוד וכגיבוי.
**תלויות:** PowerShell 5.1 המובנה ב-Windows. אפס התקנות ואפס ספריות חיצוניות.

## הארכיטקטורה בשורה אחת

משימה מתוזמנת (SYSTEM, כל 2 דקות) ← `clear-queue.ps1` ← `engine.ps1` מחליט מי תקוע ← `spooler-api.ps1` מוחק ← יומן ב-`data\logs`.

| קובץ | תפקיד |
|---|---|
| `src/engine.ps1` | **ההחלטה** מי תקוע. קוד טהור בלי קריאות ל-Windows, ולכן ניתן לבדיקה מלאה |
| `src/clear-queue.ps1` | הסריקה: קורא את התור, מפעיל את המנוע, מוחק, רושם ביומן |
| `src/spooler-api.ps1` | P/Invoke ל-`winspool.drv` — מחיקה שעובדת גם בלי הרשאות מנהל |
| `src/settings-ui.ps1` | חלון WinForms עברי RTL. `-SelfTest` בונה אותו בלי להציג |
| `src/install-task.ps1` | `install` / `remove` / `status` של המשימה המתוזמנת |
| `src/common.ps1` | הגדרות, יומן, מצב, כתיבה אטומית |
| `src/launch.ps1` | מה ש-`הפעלה.bat` מריץ: `Unblock-File` על התיקייה (לקבצים שנפרסו מ-ZIP) ואז העלאת הרשאות |

## למה המנוע מורכב ולא "מחק הכל"

מחיקה גורפת כל 2 דקות הייתה הורגת גם הדפסה שמתקדמת כרגע. לכן המנוע שומר בכל סריקה כמה עמודים כל עבודה הדפיסה, ומוחק רק מה שלא זז. עבודה של 500 עמודים שרצה חצי שעה לא תימחק אף פעם, כל זמן שמונה העמודים שלה עולה.

כל כלל הוא **הגדרה בחלון**, לא קוד: סף הדקות, מה לעשות בשגיאה, אם לגעת בעבודה שממתינה לנייר, ואחרי כמה נסיונות כושלים לאפס את שירות ההדפסה.

## ארבע מלכודות Windows שנתגלו בבנייה

1. **`Remove-PrintJob` מחזיר "Access was denied" בלי הרשאות מנהל** (אומת על המחשב הזה). לכן המחיקה עוברת דרך `SetJob(JOB_CONTROL_DELETE)` של `winspool.drv`, שמצליח גם למשתמש רגיל על העבודות שלו. `Remove-PrintJob` נשאר כגיבוי שני. **זו הסיבה שהפרויקט לא מסתפק בפקודות המובנות.**
2. **`[System.IO.File]::Replace` לא מקבל `$null`** — PowerShell ממיר אותו למחרוזת ריקה ו-.NET זורק `The path is not of a legal form`. הפתרון: `[NullString]::Value`.
3. **`Write-Host` לא זורם בצינור** — תיבת "בדוק עכשיו" חזרה ריקה. כל הפלט ב-`Write-Output`.
4. **משימה שרצה תחת SYSTEM אינה נראית למשתמש רגיל.** `Get-ScheduledTask` מחזיר "לא נמצא", `Get-ScheduledTaskInfo` ו-`schtasks /query` מחזירים Access denied — בזמן שהמשימה מותקנת ורצה. הממשק הכריז "לא מותקנת" בשקר. גרוע מזה: `Test-Path` על `HKLM:\...\TaskCache\Tree\<שם>` מחזיר **True לכל שם, גם מומצא** — אורקל שקרי שלא לסמוך עליו. הפתרון: ממשק ה-COM `Schedule.Service`, שמבדיל בין `0x80070005` (אין הרשאה ⇒ המשימה קיימת) לבין `0x80070002` (לא נמצא ⇒ אינה קיימת). יש בדיקת רגרסיה על זיהוי הכזב.

ובנוסף, כלל שתקף לכל הפרויקט: **כל קובץ `.ps1` חייב להיות UTF-8 עם BOM**, אחרת PowerShell 5.1 שובר את העברית שבתוכו.

## בדיקות

```
powershell -ExecutionPolicy Bypass -File tests\run-tests.ps1          # 18 בדיקות למנוע
powershell -ExecutionPolicy Bypass -File tests\integration-test.ps1   # 6 בדיקות אמת
powershell -ExecutionPolicy Bypass -File src\settings-ui.ps1 -SelfTest  # בניית החלון
```

`integration-test.ps1` (6 בדיקות) יוצרת עבודת הדפסה **אמיתית** בתור ומיד משהה אותה דרך ה-API, כך שהמדפסת לא מקבלת כלום ולא מודפס נייר. אחר כך היא מריצה את המוצר עצמו (בתיקיית נתונים מבודדת, `-DataDir`) ומוודאת שהעבודה נמחקה בפועל. זו הבדיקה שחשפה את הבאגים למעלה.

## גרסת ה-exe (`exe\`) — להפצה

שני מימושים של אותו מוצר, ובכוונה:

| | PowerShell (`src\`) | C# (`exe\`) |
|---|---|---|
| מה זה | תיקיית סקריפטים | קובץ אחד, ~92 ק"ב |
| למי | המחשב של הת"ת (מותקן ורץ) | הפצה לאנשים אחרים |
| תלויות | PowerShell 5.1 | .NET Framework 4.x (מובנה) |
| הגדרות ויומן | `data\` לצד הקוד | `%ProgramData%\PrintQueueCleaner` |
| בדיקות | `tests\` (24) | בתוך ה-exe, `--selftest` (23) |

**הבנייה:** `powershell -ExecutionPolicy Bypass -File exe\build.ps1`
מקמפלת עם `csc.exe` של .NET Framework 4.8 שמגיע מובנה בכל Windows — **בלי Visual Studio ובלי dotnet SDK.** המחיר: המהדר המובנה הוא C# 5, ולכן המקור נכתב בלי `exception filters` ובלי `string interpolation`. זו החלטה מכוונת: הבנייה עובדת בכל מחשב Windows, גם בעוד שנתיים, גם בלי אינטרנט.

`build.ps1` מריץ בסוף את `--selftest` ואת `--formcheck` ונכשל אם משהו לא עבר. אין "נבנה בהצלחה" בלי בדיקות.

**שיפור מהותי על גרסת ה-PowerShell:** מצב העבודה מגיע מ-`EnumJobs` כדגלי ביטים אמיתיים (`JOB_STATUS_*`) ולא כמחרוזת שצריך לחפש בה מילים. `Printing, Retained` היא עבודה שעוד מדפיסה — מי שבודק `Retained` לפני `Printing` הורג הדפסה פעילה, ועם דגלים זה לא תלוי בניסוח של Windows.

**האייקון** נוצר ב-`exe\make-icon.ps1` (GDI+ טהור, בלי נכסים של מיקרוסופט).

### ארבע מלכודות נוספות שעלו בבניית ה-exe

5. **`System.Drawing.Icon` לא תומך ברשומות PNG בתוך ICO.** קובץ שכולו PNG נראה תקין, נטען, ואז `ToBitmap()` זורק `Requested range extends past the end of the array`. המבנה התקני: DIB קלאסי לגדלים הקטנים, PNG רק ל-256. `make-icon.ps1` מאמת בסוף שכל גודל מומר לתמונה — זו הבדיקה שתפסה את זה.
6. **PowerShell מפרק מערך בתים שפונקציה מחזירה ל-`Object[]`**, ואז `BinaryWriter.Write` בוחר העמסה אחרת וכותב כלום. ה-ICO יצא 0.1 ק"ב בלי שום שגיאה. הפתרון: `[byte[]]` מפורש.
7. **`winexe` אינו מחזיר פלט ו-PowerShell אינו ממתין לו.** `& $exe --selftest` חוזר מיד וריק. בתוך ה-exe: `AttachConsole` רק כשאין ידית פלט תקינה, אחרת כופים UTF-8 על הזרם (אחרת העברית יוצאת ANSI בקובץ). מבחוץ: `Start-Process -Wait -RedirectStandardOutput`.
8. **`Console.OutputEncoding` זורק `The handle is invalid`** כשאין קונסולה אמיתית. חייב להיות עטוף, או להיקבע רק כשבאמת יש קונסולה.
